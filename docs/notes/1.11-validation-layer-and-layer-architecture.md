# Validation Layer & Vulkan 的 Layer 架构

> Validation Layer = 你的代码和 Driver 之间的安全检查员，Debug 模式下拦截所有 Vulkan 调用，在错误数据塞给 GPU 之前就告诉你错在哪。Release 构建中完全移除，零开销。

## 为什么 Vulkan 必须有这玩意

Vulkan 的设计哲学是"信任开发者"——Driver 假设你传进来的每样东西都是对的。如果不对，结果是**未定义行为**（黑屏、花屏、崩溃、或者这次能跑下次不行）。

和 OpenGL/GLES 的致命区别：

| | OpenGL / GLES | Vulkan |
|---|---|---|
| **错误检查** | Driver 内置，每帧强制运行 | 可选，通过 Layer 外挂 |
| **Layer 体系** | 不存在 | `VK_LAYER_*`，Loader 原生支持链式拦截 |
| **Profiler 注入方式** | `.so` / `.dll` 劫持（hack） | 环境变量指定，官方 API |
| **调试信息质量** | `glGetError()` → `GL_INVALID_OPERATION`（就这） | 文件名 + 行号 + 详细描述 + 修复建议 |

## 具体检查什么

| 类别 | 检查内容 |
|------|---------|
| **参数校验** | `VkSubmitInfo::sType` 写对了吗？`pNext` 链合法吗？ |
| **生命周期** | 这个 `VkBuffer` 在用它之前 Destroy 了吗？ |
| **同步** | Pipeline Barrier 的 `srcStageMask` 和 `dstStageMask` 合理吗？ |
| **Image Layout** | 你用 `VK_IMAGE_LAYOUT_COLOR_ATTACHMENT_OPTIMAL` 作为 Shader 输入时，是否先做了 Transition？ |
| **Descriptor** | Draw Call 引用的 Descriptor Set 是否已绑定、是否有效？ |
| **内存** | `vkMapMemory` 之前是否 `vkAllocateMemory` 了？ |
| **最佳实践** | 你没开 `VK_EXT_robustness2` 却用了 out-of-bounds 访问 |

## Layer 是链式架构，不是替换

所有激活的 Layer 被 Vulkan Loader 串成一条链——Profiler（RenderDoc/Snapdragon）不会替换你的 Validation Layer，而是额外加一层：

```
你的 App
  → vkDraw(...)
    → VK_LAYER_KHRONOS_validation  // 检查参数合法性
      → VK_LAYER_RENDERDOC_Capture // 拦截、录制所有 API 调用
        → VK_LAYER_LUNARG_monitor  // 显示 FPS 叠加层
          → Vulkan Driver           // 真正干活
            → GPU
```

每个 Layer 暴露 `vkGetInstanceProcAddr` / `vkGetDeviceProcAddr`，Loader 顺着链问"你能处理哪些函数？"——能处理的拦截，不处理的转发。

顺序很重要：**Validation 放最上面（离 App 最近），Profiler 放 Validation 和 Driver 之间。** 这样先捕获错误，再录制合法调用。

## 为什么 `validationLayers` 只是 `vector<const char*>`？

因为 Layer 是**点名激活**的系统组件——它是预装在 SDK 里的 `.dll` / `.so` 文件，你不创建、不管理、不销毁它。一个字符串就够了。

精细配置（比如只检查同步不检查 shader）不通过 API 参数，而是走 `vk_layer_settings.txt` 配置文件——不需要重新编译就能调 Layer 行为。

| 概念 | 表示方式 | 为什么 |
|------|---------|--------|
| **Layer** | `const char*`（名字） | 预装的 dll，你只管点名激活 |
| **Instance / Device** | `VkInstance` / `VkDevice`（handle） | 你要创建、管理生命周期、最后销毁 |
| **Image / Buffer** | `VkImage` / `VkBuffer`（handle） | 同上 |

## OpenGL ES 为什么做不到同样的事

因为 GLES 没有官方 Layer 接口，所有工具只能靠**拦截底层系统调用**（LD_PRELOAD / DLL 代理 / APK 修改），本质上是"假冒 Driver"，不像 Vulkan 那样正规注册到一个公开的链里。这就是"为什么 Vulkan 比 OpenGL 快且好调试"的核心答案之一。

## 各工具的 Layer 名字

| 工具 | Layer 名字 |
|------|-----------|
| **Khronos Validation** | `VK_LAYER_KHRONOS_validation` |
| **RenderDoc** | `VK_LAYER_RENDERDOC_Capture` |
| **Snapdragon Profiler** | `VK_LAYER_QCOM_SnapdragonProfiler` |
| **Arm PerfDoc**（最佳实践检查） | `VK_LAYER_ARM_perfdoc` |
| **NVIDIA Nsight** | `VK_LAYER_NV_nsight` |

## 一句话记住

> Validation Layer = 你"租"的安全检查员——Debug 时付费，Release 时不付。Vulkan 把检查做成可选外挂的插件体系，每个工具各取所需地拦截调用，是它比 OpenGL 快且更好调试的根本原因。
