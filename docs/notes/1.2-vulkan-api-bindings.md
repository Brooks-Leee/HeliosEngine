# Vulkan API 绑定：三层怎么选

> `vulkan.h`（C）→ `vulkan.hpp`（C++ UniqueHandle）→ `vulkan.hpp`（vk::raii）

## 三层对比

```cpp
// 第 0 层：纯 C API
#include <vulkan/vulkan.h>
VkInstance instance;
vkCreateInstance(&createInfo, nullptr, &instance);
vkDestroyInstance(instance, nullptr);            // 手动

// 第 1 层：vulkan.hpp UniqueHandle（我们用这个）
#include <vulkan/vulkan.hpp>
vk::UniqueInstance instance = vk::createInstanceUnique(createInfo);
// 出作用域自动销毁 — RAII

// 第 2 层：vulkan.hpp vk::raii::
#include <vulkan/vulkan_raii.hpp>
vk::raii::Instance instance(context, createInfo);
// 也自动销毁，但额外绑了 Context（dispatch table），更重
```

| | C API | UniqueHandle | vk::raii |
|---|---|---|---|
| 头文件 | `vulkan.h` | `vulkan.hpp` | `vulkan.hpp` + `vulkan_raii.hpp` |
| 销毁 | 手动 | 自动 RAII | 自动 RAII |
| 取原始 handle | 本来就是 | `.get()` | `*` 解引用 |
| 传给 C API | 直接传 | `&handle` / `.get()` | 需要 `*handle` |
| 额外功能 | 无 | 无 | debug 名、Context 绑定 |
| 复杂度 | 最低 | 低 | 中 |

## 我们为什么选 UniqueHandle

1. 比 C API 安全——不靠记忆调 `vkDestroy`
2. 比 vk::raii 轻——不需要额外的 Context 对象
3. 和项目的 Win32 Window RAII 哲学一致

## 注意：`VK_NO_PROTOTYPES` + 动态加载

如果定义了 `VK_NO_PROTOTYPES`，vulkan.hpp 走动态加载路线——所有函数通过 `DispatchLoaderDynamic` 调用，extension 函数（如 debug utils）也能正确工作。

初始化三步：
```cpp
// 1. 从 vulkan-1.dll 加载入口
HMODULE vulkanDll = LoadLibraryA("vulkan-1.dll");
auto fn = GetProcAddress(vulkanDll, "vkGetInstanceProcAddr");
VULKAN_HPP_DEFAULT_DISPATCHER.init(fn);

// 2. 创建 Instance 后初始化 instance 级函数
m_instance = vk::createInstanceUnique(createInfo);
VULKAN_HPP_DEFAULT_DISPATCHER.init(m_instance.get());

// 3. 创建 Device 后初始化 device 级函数
m_device = m_physicalDevice.createDeviceUnique(deviceCI);
VULKAN_HPP_DEFAULT_DISPATCHER.init(m_device.get());
```
