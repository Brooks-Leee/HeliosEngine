# Vulkan Present Mode

> GPU 产出帧的节奏 ≠ 显示器刷新的节奏。四种模式解决这个协调问题。

## 两个角色

| | GPU（生产者） | 显示器（消费者） |
|---|---|---|
| 节奏 | 不固定（5ms ~ 30ms） | 固定（60Hz = 16.6ms） |
| 问题 | 产出太快/太慢怎么办 | |

## 四种模式

### `IMMEDIATE` — 不等，直接上

```
GPU 好了 → 立刻覆盖 framebuffer → 不管显示器刷到哪了
结果：画面撕裂（tearing）——上半截旧帧，下半截新帧
用在哪：电竞，追求最低延迟
```

### `FIFO` — 排队（V-Sync）

```
GPU 好了 → 放进队列 → 队满就等
显示器到点 → 从队列取一帧
结果：画面完美，无撕裂
代价：延迟高（GPU 快了要排队等显示器）
Vulkan 规范强制所有实现必须支持 ← 我们目前用这个
```

### `FIFO_RELAXED` — 排队但允许迟到

```
GPU 按时 → 和 FIFO 一样排队
GPU 晚了 → 不等了，直接上，可能撕裂
用在哪：大部分时候 VSync，偶尔掉帧不雪崩
```

### `MAILBOX` — 只保留最新一封

```
GPU 好了 → 放进队列
队列有旧的？→ 丢掉旧的
GPU 永不阻塞 ← 游戏引擎首选（UE/Unity 默认）
代价：浪费 GPU 算力（渲染了但没显示的帧白算了）
```

## 一张表

| 模式 | 撕裂 | 延迟 | GPU 阻塞 | 场景 |
|------|------|------|----------|------|
| IMMEDIATE | 有 | 最低 | 否 | 电竞 |
| FIFO | 无 | 高 | 是 | 视频、保证可用 |
| FIFO_RELAXED | 偶尔 | 中 | 部分 | 掉帧容忍 |
| MAILBOX | 无 | 低 | 否 | **游戏引擎** |

## 我们的代码

```cpp
// 现在 — FIFO，因为规范强制支持，不需要查询
vk::PresentModeKHR presentMode = vk::PresentModeKHR::eFifo;

// 以后 — 查询 MAILBOX 是否可用，优先使用
auto modes = physicalDevice.getSurfacePresentModesKHR(surface);
for (auto mode : modes) {
    if (mode == vk::PresentModeKHR::eMailbox) { presentMode = mode; break; }
}
```

## 和 `waitIdle()` 的叠加

FIFO 本身卡 CPU（队列满时 acquire 阻塞），我们还在后面加了 `waitIdle()`——等于卡两次。这是故意为之：先保证正确性，Phase 3 用 Fence 替换 waitIdle 实现多帧并行。
