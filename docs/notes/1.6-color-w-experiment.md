# 颜色 + W 实验

> 在 VS 里给三个顶点不同颜色、不同 w，观察透视除法 + 透视修正插值。

## Shader

```glsl
// triangle.vert
vec2 positions[3] = vec2[](
    vec2(0.0, -0.5),   // 顶部
    vec2(0.5, 0.5),    // 右下
    vec2(-0.5, 0.5)    // 左下
);

vec3 colors[3] = vec3[](
    vec3(1.0, 0.0, 0.0),   // 红 — 顶部
    vec3(0.0, 1.0, 0.0),   // 绿 — 右下
    vec3(0.0, 0.0, 1.0)    // 蓝 — 左下
);

float ws[3] = float[](
    1.0,    // 顶部：w=1，正常
    1.0,    // 右下：w=1，正常
    2.0     // 左下：w=2，除后往中心缩一半
);

layout(location = 0) out vec3 fragColor;

void main() {
    gl_Position = vec4(positions[gl_VertexIndex], 0.0, ws[gl_VertexIndex]);
    fragColor = colors[gl_VertexIndex];
}
```

## 观察到的两个现象

### 1. 左下顶点往中心收缩 — 透视除法

```
左下顶点：(-0.5, 0.5, 0.0, 2.0)  →  ÷2  →  (-0.25, 0.25, 0.0)
            ↑ Clip Space                           ↑ NDC，往中心缩了一半
```

w 变大一倍 → 屏幕位置缩一半。这就是透视投影"远小近大"的数学原理。

### 2. 颜色不对称渐变 — 透视修正插值

GPU 光栅化时不只是线性混合颜色，而是考虑三个顶点的 w 做透视修正：
- 蓝色区域被 w 压缩了
- 红→绿的过渡占更大面积

## 关键理解

- 不用深度缓冲就能看到 w 的效果——改 w 直接改变屏幕位置
- 颜色插值不是简单线性——GPU 在光栅化阶段自动做 `attribute/w` 的透视修正
- `gl_FragCoord.z` 存的是深度 buffer 值 `[0,1]`，`gl_FragCoord.xy` 是屏幕像素坐标
