# 坐标空间：Clip Space → NDC → Screen Space

> P 矩阵不挤压，透视除法才挤压。矩阵是线性的，除法是非线性的。

## 一图串全程

```
空间               x      y      z               w              谁做的
────────────────   ──     ──     ──              ──              ────
Object Space       坐标    坐标    坐标             1.0            Model矩阵
    ↓ Model × View
View Space         坐标    坐标    相机距离(-z)      1.0            View矩阵
    ↓ Projection Matrix
Clip Space         坐标    坐标    A·z+B（线性）    -z（原始深度）  投影矩阵
    ↓ 透视除法（GPU硬件，÷w）
NDC               坐标    坐标    (A·z+B)/(-z)     消失            硬件自动
    ↓ Viewport变换
Screen Space       像素    像素    [0,1]存深度缓冲   —              硬件自动
```

## Clip Space 和 NDC 的区别

> Clip Space = NDC × w。一个位置的两种表达。差一个除以 w。

| | Clip Space | NDC |
|---|---|---|
| 维度 | 4D (x, y, z, w) | 3D (x, y, z) |
| w | 还活着 | 已除掉了 |
| 谁输出 | Vertex Shader (`gl_Position`) | GPU 硬件自动算 |
| 裁剪在哪做 | ✅ 用 w 对比 `-w ≤ x ≤ w` | ❌ |
| 范围 | `-w ≤ x ≤ w`, `0 ≤ z ≤ w`（Vulkan） | `-1 ≤ x ≤ 1`, `0 ≤ z ≤ 1` |

```
例子：
  gl_Position = (3, 0, 0.05, 6)     ← Clip Space
                                       ↓ 裁剪：|3| ≤ 6 → 通过 ✓
                                       ↓ 透视除法
  NDC = (0.5, 0, 0.008)              ← NDC
```

## 为什么裁剪在除法之前

```
除法前（Clip Space）：用 w 做边界，不除法 → 不怕 w=0
除法后（NDC）：       w 已经被消掉了，无法回溯

w=0 是什么情况？顶点在相机平面上（z_view=0），除法会炸。
在 Clip Space 直接判断 |x| ≤ w 就不需要做除法，w=0 也能正确处理。
```

## 投影矩阵对三个分量做了什么

### x/y — 单纯缩放

```
x_clip = (1/tan(fov/2)) / aspect * x_view
y_clip = (1/tan(fov/2)) * y_view

只缩放，没有别的 tricks。除法后做近大远小。
```

### z — 分子准备

```
z_clip = A * z_view + B

其中（Vulkan [0,1] 深度范围）：
  A = far / (far - near)
  B = near * far / (far - near)

z_clip 是线性的（一次函数）。
```

### w — 分母准备

```
w_clip = -z_view

把 View Space 的原始深度抄进 w。
每个顶点有自己的 z_view → 每个顶点有自己的 w → 除法后各有各的缩放比例。
```

## 透视除法的非线性来源

```
z_ndc = z_clip / w_clip
      = (A * z_view + B) / (-z_view)
      = -A - B / z_view
              ^^^^^^^
              1/z_view！非线性就从这里来

z_clip 是线性的（直线的 z_view 一次函数）
w_clip 也是线性的（直接等于 -z_view）
但两者相除 → 非线性曲线：近处精度高，远处精度低
```

## 为什么矩阵做不到透视除法的事

```
矩阵乘法 = 用常数乘输入
  output = m * input
  m 在整个 draw call 里不变，所有顶点用同一个矩阵

透视除法需要：
  顶点 A（近，深度 1）→ 除以 1
  顶点 B（中，深度 5）→ 除以 5
  顶点 C（远，深度 50）→ 除以 50
  每顶点除不同的数，矩阵是死的，做不到

Projection 矩阵的 trick：
  不自己做除法，而是把每个顶点的深度抄进对应的 w
  让 GPU 硬件做逐顶点的除法
```

## z vs w vs 归一化深度

| 名称 | 位置 | 公式 | 线性？ | 存哪 |
|------|------|------|--------|------|
| z_clip | `gl_Position.z` | A·z_view + B | ✅ 线性 | VS 输出 |
| w_clip | `gl_Position.w` | -z_view | ✅ 线性 | VS 输出 |
| z_ndc (归一化深度) | 透视除法后 | z_clip / w_clip | ❌ 非线性 | 深度buffer `[0,1]` |

**z 从头到尾都在——只是形态从线性变成非线性。**

## NDC [-1,1] 是约定不是必然

```
GPU 实际裁剪条件：-w ≤ x ≤ w（不除 w）
NDC 的 [-1,1] 是除 w 之后的自然结果：-1 ≤ x/w ≤ 1

为什么用 [-1,1]？
  解耦分辨率：shader/matrix 永远输出 [-1,1]
              不管 720p 还是 4K，viewport 变换一步映射到实际像素
              前面的数学全部不用改
```

## 屏幕空间效果全在这套坐标系上

| 效果 | 运算空间 | 为什么 |
|------|---------|--------|
| 边缘检测（描边） | 屏幕空间 UV | 直接在邻居像素比较深度/法线，不转任何空间 |
| SSAO | View Space 采样，NDC 取深度 | 半球方向需要相对视线，深度比较在 buffer 里 |
| SSR（屏幕反射） | NDC | ray march 每一步都在 NDC，全程不转世界 |
| 深度反推世界坐标 | NDC → View → World | 需要知道像素的世界位置时才走这条路 |
| Deferred Decals | Screen Space → World | 需要判断"这个像素在不在这面墙的世界范围内" |
| Shadow Map | 灯光视角 NDC | 从灯光 VP 矩阵渲染深度 → 主相机采样比较 |

## Vulkan vs OpenGL NDC 差异

| | Vulkan | OpenGL |
|---|---|---|
| Y 轴 | ↓ 向下 | ↑ 向上 |
| Z 范围 | [0, 1] | [-1, 1] |
| 原点 | 左上角 | 左下角 |

## 一句话记住

> VS 输出 Clip Space（4D）→ GPU 裁剪（用 w 判断）→ GPU 透视除法（÷w）→ NDC（3D）→ Viewport → 屏幕像素。矩阵是线性的只做分子分母的准备工作，GPU 硬件的除法一步做出非线性深度分布 + 近大远小。
