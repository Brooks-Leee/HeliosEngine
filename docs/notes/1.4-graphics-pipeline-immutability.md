# Graphics Pipeline 不可变性

> Pipeline 创建时锁死几乎所有状态，运行时不能改——只能重建。

## 老 API 的问题（OpenGL / D3D11）

```cpp
// 你随时改，驱动在后面疯狂猜测
glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);
glEnable(GL_DEPTH_TEST);
draw();
glBlendFunc(GL_ONE, GL_ONE);  // 又改了
draw();
// 驱动：他又改了！我得重编译 GPU 指令 ← 卡顿的根源
```

## Vulkan/DX12 的解决方案

```cpp
// 创建时把状态全部锁死
vk::GraphicsPipelineCreateInfo pipelineCI;
pipelineCI.pColorBlendState    = &blendState;    // 混合模式 ← 锁死
pipelineCI.pRasterizationState = &rasterizer;    // 光栅化  ← 锁死
pipelineCI.pDepthStencilState  = &depthStencil;  // 深度    ← 锁死
pipelineCI.pStages             = shaderStages;   // Shader  ← 锁死
pipelineCI.renderPass          = renderPass;     // 格式    ← 锁死

// 创建后这些全部不可变
auto result = device.createGraphicsPipelineUnique(nullptr, pipelineCI);
```

**代价**：换一种混合模式 = 创建一个新 Pipeline。一个游戏可能有几十上百个 Pipeline。

**收益**：创建时驱动就编译好 GPU 指令了，运行时绑定即可——零开销切换。

## Vulkan Pipeline vs DX12 PSO

| Vulkan | DX12 |
|--------|------|
| `vk::GraphicsPipelineCreateInfo` | `D3D12_GRAPHICS_PIPELINE_STATE_DESC` |
| Shader stages | VS/PS/GS/HS/DS |
| Vertex input layout | InputLayout |
| Rasterizer (cull/fill) | RasterizerState |
| Depth/Stencil | DepthStencilState |
| Blend | BlendState |
| Multisampling | SampleDesc |
| RenderPass | RTVFormat/DSVFormat |
| PipelineLayout | RootSignature |

**同一个设计哲学——殊途同归。**

## 可变的例外：Dynamic State

部分状态可以标记为 dynamic，运行时修改：

```cpp
std::vector<vk::DynamicState> dynamicStates = {
    vk::DynamicState::eViewport,  // 窗口 resize
    vk::DynamicState::eScissor,   // 裁剪区域
};

// 运行时改，不需要新建 Pipeline
cmd.setViewport(0, 1, &viewport);
cmd.setScissor(0, 1, &scissor);
```

## 对引擎设计的影响

Phase 4 Material System 会面临 **组合爆炸**：

```
不同 Shader × 不同 Blend × 不同 Depth × 不同 Cull = 几百个 Pipeline
```

解决方案：**Pipeline Cache**——用状态 hash 做 key，创建过的 Pipeline 缓存起来复用。

```
std::unordered_map<Hash, Pipeline> pipelineCache;
// key = shader + blend + depth + raster 的哈希
```

UE 的做法：加载界面预编译 PSO，Unity HDRP 同理。
