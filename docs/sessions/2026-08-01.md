## 22:49 — [agent:Claude] — 战略决策：转向 Godot strand-fur 桌面宠物；HeliosEngine 重新定位

### 背景
用户提出新产品：**桌面宠物陪伴**（Steam 已有类型），核心竞争力 = **写实可交互毛发**（strand fur，重度依赖 compute shader），跨平台 PC + 移动端。逐项评估 UE / 自研 / Cocos / Unity / Godot。

### 决策（记录）
1. **产品引擎选 Godot（fork/深度改造）**：全开源可改管线（RenderingDevice 层）+ 三后端（D3D12/Vulkan/Metal，4.6 起 Windows 默认 D3D12）+ compute 一等公民 + 桌面透明窗原生支持
2. **自研引擎出局**：跨平台 RHI（DX12/Vulkan/Metal）是 solo 死亡区；引擎 80% 是商品，壁垒是毛发技术不是引擎
3. **UE 出局**（仅当放弃移动端才考虑 Groom）；**Cocos 出局**（半开源、架构浅、面向中国移动小游戏）；**Unity 出局**（黑盒，不能改核心管线）
4. **HeliosEngine 重新定位：暂停，不放弃**——从"唯一学习载体"变为"深度 RHI 参考工具"：在宠物项目里遇到 compute/barrier/DX12 底层问题时按需回来挖
5. **学习与产品合一**：strand 管线（compute 模拟 + 曲线光栅化 + dual scattering）本身就是引擎级图形工作；产品驱动学习，学习嵌在产品里
6. **转路径**：M0 compute spike（Godot RD 跑 strand compute + 渲染，2-4 周）→ M1 shell fur → M2 strand 质量分级 → M3 交互（抚摸/吹风 → 引导发丝 XPBD）→ M4 产品工程（透明窗/常驻低功耗/打包）。模型动画走采购（Sketchfab + Mixamo）

### 卡点
- 移动端 strand 密度有硬件上限 → 必须一开始就设计质量分级（PC 高密度 / 移动低密度或 shell 降级）
